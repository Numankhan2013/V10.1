## 3. SOURCE-PDF EXPLANATION DECISION — BINDING

**The original PDF is the source of truth.**

Do NOT reconstruct complex medical explanations heuristically from flattened JSON.

Previous heuristic parsing/reconstruction caused:
- destroyed tables
- broken bullets
- corrupted glyphs
- duplicated headings
- scientific-notation corruption
- `Table rendering failed`
- semantically incoherent explanations

That approach was rejected.

Instead:
- locate the original solution in the source PDF
- render the original PDF pixels in-app
- crop only to the relevant solution segment where mappings exist
- preserve tables, diagrams, graphs, figures and source wording
- allow zoom/full-screen/pan

This decision is binding unless the user explicitly changes it.

## 6. BACKUP / RESTORE — V10.4 FUNCTIONAL FEATURE

The user explicitly wants a way to preserve all personal app history so it can be restored after deletion/reinstallation.

Backup should include user state such as:
- question progress
- attempts/history
- bookmarks
- wrong-question history
- CBT/test history
- answers/results
- statistics
- streak information
- spaced-review information
- preferences/settings
- future personalization state

Do NOT duplicate the bundled source PDFs inside the user backup.

### Backup format

Use a versioned backup file, e.g.:
`QBank_Backup_YYYY-MM-DD.qbbackup`

It should contain:
- manifest
- backup schema version
- user state
- integrity/checksum information
- app/version metadata where useful

### Required actions
- Backup Now
- Restore Backup
- Automatic Backup

Automatic backup options requested by user:
- Off
- Every 3 days
- Weekly

Show backup status such as:
- Last backup date/time
- Backup destination/status

### Restore safety

Restore must:
1. validate format
2. validate schema version
3. validate integrity
4. show/confirm what is being restored where appropriate
5. restore safely
6. rebuild derived statistics if needed
7. re-render cleanly

Never blindly overwrite current state with an invalid/corrupt backup.

### Google Drive

Target: automatic/manual backup to Google Drive or an equivalent user-accessible cloud destination.

Architecture should keep the backup format independent of Google Drive so future storage destinations can be supported without changing the state model.
